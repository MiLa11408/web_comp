一、作品概述

1.1 一句话定位

“机忆书库”是一座可以在浏览器里走进去的 AI 知识档案馆：读者从门厅领证入馆，在 3D 阅览室的书架上取书、翻开、阅读，也可以乘黄铜电梯去不同楼层、在星图上观察概念关系、在卡片目录里检索，或参与残页、失窃页、暗门等馆藏玩法。

作品把“AI 知识”从一条条链接和列表，重新组织成有空间、有路径、有仪式感的阅读经验。它不提供“问一句答一句”的聊天框，而是保留“自己走一趟”的部分：路线可以给你，判断尽量留给你。

1.2 要解决的问题

  • AI 知识碎片化：新闻、论文、教程、观点散落在不同平台，初学者缺少一条能按时间、人物、机构串起来的主线。
  • 检索结果缺少上下文：关键词能给出链接，却很难说明“这条结果在整个 AI 史里处在什么位置”。
  • 科普内容难读：术语密度高、句子长，读者容易在开头三段放弃。
  • 展示型网站缺少“留下来”的理由：看完一页就走，没有探索、收集与回访动机。

1.3 对大赛主题的回应

大赛强调“AI 与网页载体深度融合”，而不只是把 AI 当作绘图或编码工具。本作品的回应是：让 AI 成为内容组织与交互的一部分，而不是页面上的一个按钮。

  • AI 作为馆藏：448 章内容本身就是一部可检索、可漫游的 AI 通史，覆盖符号主义、神经网络、产业、治理与前沿。
  • AI 作为理解工具：概念手册把 16 个核心概念拆成“一句话、生活类比、准确解释、常见误解、四镜路径”；CNN 与注意力演示把卷积、softmax 的计算过程直接画出来。
  • AI 作为内容管线：前沿观察每日从 arXiv 与官方 RSS 取源，经大模型编译成中文科普新闻，再进入馆内检索。

1.4 作品一览

作品由“内容、技术、玩法”三条线组成，评委可以从下表快速建立整体认识：

二、创意设计

2.1 灵感来源

灵感来自闭馆后的图书馆：灯还亮着，书架还在，但人已经走了。这个场景天然适合承载“知识仍在，等待被重新发现”的主题。项目把 AI 发展史看作一座馆藏：有的书是公开的旧纸，有的是内部蓝图，有的是机密账簿，最上层则封着蜡与帷幕。

视觉上采用暗色古籍外壳：暖木、黄铜、旧纸、蜡封；交互上借用真实图书馆的动作：领证、乘电梯、抽书、翻页、盖章、放大镜、卡片目录。读者不需要先学一套新 UI，就能凭直觉行动。

网页元素对应现实承载的功能

2.4 背景故事与文风

不同馆藏用不同的叙事语气，避免全书一个腔调：

  • 楼层档案：L1 旧纸、L2 蓝图、L3 账簿、L4 蜡封；同一段史实，在不同楼层由不同馆员用不同口吻讲述。
  • 页边注：馆长口吻的短评，只基于正文已核验的事实，不引入新事实；作用是给硬知识一个喘气的出口。
  • 残页：残缺叙事，关键结局处用“纸页被撕去 / 烧毁”或缺字符号，只给走向不给答案。
  • 失窃页 / 躁动书页：短篇悬疑 + 收容记录；读者先读到异常，再决定追回或归位。
  • 假如之书：三条科技树（符号 / 神经 / 具身），每本“序章 + 五幕 + 尾声”，走的是另一条历史线。
  • 未写之书：读者给出假设，AI 当场续写 500–900 字。

3.2 技术栈选择

层次选型选择理由
3D 渲染three.js r187（本地 vendor）生态成熟、文档充足；直接以 ES module 引入，不引入 React Three Fiber 等额外抽象，便于控制 draw call 与后处理链。
物理Rapier（wasm）书本能真实静置、坠落与堆叠；移动端直接跳过，避免下载 4.3MB 物理包。
前端框架原生 HTML / CSS / JavaScript零构建、零框架运行时；页面本身就是交付物，评委打开即可运行，减少工具链风险。
后端Fastify 5 + node:sqlite轻量、启动快；SQLite 单文件便于备份与迁移，适合单机部署的参赛作品。
内容Markdown + JSON写作者只关心正文；结构、关系、楼层、标签全部数据化，便于校验与批量生成。
检索自建倒排索引中文用二元组切分，英文按词；无需外部搜索引擎，启动时构建，查询稳定在毫秒级。
音效WebAudio 程序生成不依赖音频文件；翻书、脚步、电梯、星图 pad 全部合成，体积为零。
部署nginx + systemd + Let's Encrypt子路径 /ai/ 反代；HTTPS 使用 IP 证书，评委打开不撞“不安全”提示。

3.3 设计原则

  • 内容优先：视觉与交互服务于“读到内容”，不为 3D 而 3D；任何 3D 操作都有 2D 替代路径。
  • 渐进增强：低配设备自动关闭阴影、后处理、物理与部分尘埃；核心阅读始终可用。
  • 单一数据源：书、章、关系、楼层、玩法状态都来自数据文件或数据库，前端不写死内容。
  • 可验证：内容有 verify 规则，交互有 E2E 断言，性能有 draw call 与首帧预算。

六、关键设计决策

决策理由与代价
不引入前端框架零构建、打开即运行；代价是 DOM 与状态管理需要手写，因此用清晰的模块边界与统一的事件入口控制复杂度。
访客只读评委与路人无需注册即可读全部内容，摩擦最小；盖章、批注、进度需要办证，形成自然的身份动机。
3D 与 2D 双路径3D 负责氛围与“逛”的体验；书架视图、总览、平面图提供快速直达。低配设备也能完成全部阅读。
物理延迟加载Rapier 4.3MB 不阻塞首屏；先出画面，再补物理。移动端完全跳过。
按材质分配反射黄铜、木头、布料、纸张分别设定 metalness / roughness / envMapIntensity；避免“全场景塑料高光”。
内容即数据448 章不写进 HTML；书籍、关系、玩法状态全部数据化，便于批量写作、校验与扩展。

七、工程质量与验证

7.1 内容校验

npm run verify 对 448 章执行结构与事实规范检查：九段齐全、字数 1500–2500、来源 3–6 条且标记已核验、关系双向引用、索书号唯一。当前结果：448 章，FAIL=0。

7.2 端到端测试

npm run test:e2e 使用 Playwright + 系统 Chrome，覆盖门厅、登录、3D 交互、阅读器、检索、星图、书轨、馆藏玩法、安全头、缓存头、移动端等。169 项全部通过。其中与 3D 相关的关键断言包括：

  • draw call 预算 ≤700（实测约 615，含后处理）；
  • 泛光后处理启用、阴影贴图 2048；
  • 展柜聚光灯在聚焦后打亮展品；
  • 星图关系线默认 0/50，定位后点亮且透明度平滑上升；
  • 门厅星点不重叠、鼠标只扰动光标附近；
  • 移动端 390px 无横向溢出。

8.2 运行方式

  1. 环境：Node.js ≥ 22.5（使用 node:sqlite）。
  2. 安装依赖：npm install。
  3. 启动：npm start，默认 http://127.0.0.1:3300/。
  4. 内容校验：npm run verify；端到端测试：npm run test:e2e。
  5. 线上：git archive HEAD → scp → /opt/machine-memory → 重启 systemd。

九、创新点与可扩展方向

9.1 创新点

  1. 空间化知识组织：把 448 章 AI 史放进四层图书馆，楼层=知识梯度，书架=主题，电梯=分区，读者用身体移动建立记忆。
  2. 可计算的阅读反馈：盖章、批注、读完、拾页、追回、收容都落到数据库，形成徽章、书榜与“今日可做”，让阅读有回访理由。
  3. 科普可视化：CNN 卷积逐格展示卷积核、特征图、ReLU、池化与分类分数；注意力用 token×token 热图展示 softmax 与多头差异。
  4. 内容管线自动化：arXiv + 官方 RSS → 中文科普编译 → 馆内检索，保持“前沿”每天更新。
  5. 克制的写实光影：Bloom + 软阴影 + 按材质反射 + 程序化体积光柱；手机上自动降级，不为效果牺牲可读性。

9.2 可扩展方向

  • 把概念手册扩展为可交互的知识图谱，支持从任意章节反向查看概念路径。
  • 为视障读者补充更完整的键盘导航与朗读标记；为低带宽环境提供纯 2D 轻量入口。
  • 将前沿编译管线开放为可配置主题，支持更多学科方向。
