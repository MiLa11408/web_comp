# CONTENT.md · 章节写作规范（每个写手开工前必读）

> 读者：任何被派来写章节的 AI Agent。本文件+你手上的任务单，就是全部要求。
> 目标：机忆书库每一章都是「非常具体的内容」——用户打开就能读到大段真实知识，而不是一堆链接。

## 0. 硬性标准（不达标会被 verify 打回）

1. 正文汉字数 **1500–2500**（不含 frontmatter、不含「档案」段来源列表的 URL）
2. 强制 9 段结构，段标题严格如下
3. 来源 3–6 条，**每条必须实际打开核验过**（第 5 节协议），`checked: true`
4. 不编造：人物、机构、年份、引文必须来自已核验来源；拿不准写「约」「据 X 记载」
5. 中文为主，术语首次出现附英文原文
6. 只写分配给你的章节文件，不碰任何其他文件

## 1. 文件格式

路径：`content/chapters/<book>/<no>.md`（book 如 `b1`，no 如 `3`）。
文件 = YAML frontmatter + 正文。frontmatter 字段表见 `docs/DATA.md` §1.2。

```markdown
---
id: "b1-c3"
book: "b1"
no: 3
title: "达特茅斯会议"
title_en: "The Dartmouth Conference"
style: "history"
year: "1956"
people:
  - name: "John McCarthy"
    org: "Dartmouth College"
tags: ["达特茅斯", "符号主义", "AI 命名"]
relations:
  prev: ["b1-c2"]
  next: ["b1-c4"]
  transit: []
features: []
summary: "1956 年夏天，一群年轻人用两个月的研讨给一门新学科命了名。"
sources:
  - title: "A Proposal for the Dartmouth Summer Research Project on Artificial Intelligence"
    url: "http://www-formal.stanford.edu/jmc/history/dartmouth/dartmouth.html"
    kind: "archive"
    license: "web"
    checked: true
    note: "用于第 1、2 段"
---

## 一句话
……
```

## 2. 九段结构（标题逐字一致）

| # | 标题 | 写什么 | 建议字数 |
|---|---|---|---|
| 1 | `## 一句话` | 它是什么，直给结论，别卖关子 | 40–80 |
| 2 | `## 时间·人物·机构` | 年份、关键人物（生卒/单位）、实验室/公司、论文名 | 150–300 |
| 3 | `## 为什么是这个时候` | 前因：什么技术/数据/钱/社会条件攒够了；被它取代或失败的先作 | 150–300 |
| 4 | `## 怎么工作` | 核心机制讲透：有流程图意像的用文字描述出来（「先……再……然后……」）；给具体数字 | 250–450 |
| 5 | `## 它改变了什么` | 跨领域影响：计算机/生物医学/产业/社会里挑 2–3 个真的、具体的 | 200–400 |
| 6 | `## 今天的地位` | 明确判定：基础仍在用 / 已被取代 / 仍有争议，给出今天的实例 | 150–300 |
| 7 | `## 争议与局限` | 谁反对过、哪里失效过；如果本来就没争议也要写「为什么当时没人反对」 | 150–300 |
| 8 | `## 关系` | 前置 / 后继 / 竞争 / 换乘，用 relations 里的真实章 id 说事；本段可写简表 | 100–200 |
| 9 | `## 档案` | 来源列表（按 frontmatter.sources 顺序）：`1. 标题（作者，年份）—— URL —— 许可`；再加一句「核验时间与结果」 | 50–150 |

写得像「书页」：可以用小标题、列举、引用；但不要用表格之外的排版噪音（无 HTML、无图片）。

## 3. 四种材质风格（style 字段）

- **history（旧纸）**：叙述感强，按时间推进，多用档案细节（会议原提案原文、当时的预算、当事人原话）；克制作者评论
- **tech（蓝图）**：机制优先，像工程文档；给具体数字（层数、参数量、误差率、训练时长）；允许「公式感」的文字描述与伪步骤
- **industry（报告）**：数据与案例驱动，给真实公司/产品/年份/金额/规模；每段至少有 1 个可查证的数字
- **frontier（档案袋）**：承认不确定性；区分「已发表结果」与「社区推测」；标注哪些是 preprint

## 4. 书写纪律

- 术语：首次出现 `Transformer（变换器架构）` 或 `Transformer`，之后用中文
- 人物：首次出现全名+年份语境，如 `Geoffrey Hinton（1947–，多伦多大学）`——生卒可以空格留白，不知道就别编
- 数字：写你核验到的确切值；区间与「约」合法
- 观点归属：学界共识可说「学界公认」；个别观点必须是谁说的就写谁说的
- 禁用：不写「众所周知」「毋庸置疑」；不写任何未核验的超链接；不粘贴大段代码

## 5. 来源核验协议（最重要）

对任务单里的「初版来源」逐条：
1. 实际打开 URL（WebFetch 或等效），确认**页面存在且内容支持该章主张**
2. 打不开 → 不换也不删之前先试：DOI 用 https://doi.org/... 解析、arXiv 用 abs 页、官方博客旧链接找 findable 存档
3. 还是不行 → 换成你**亲眼打开过**的等价来源（同一论文的 arXiv 版、官方文档、机构档案、公开书籍页），并在 note 里写「替代原引」
4. Wikipedia 只做交叉核对，不作唯一来源；每条主张至少有一个非 Wikipedia 来源
5. `checked: true` 只在你真的打开并确认后写；`note` 写「用于第 X 段」
6. 引文（直接引语）必须逐字可定位到来源页；找不到原句就改成转述

## 6. relations 与 features

- `prev/next` 引用任务单里给你的同书相邻章 id（如 b1-c2）；跨书前后关系放进 `transit`（本阶段可空数组 `[]`，除非任务单明确给了站 id）
- `features` 本阶段只写任务单标明的挂载，格式 `"kind:slug"`（如 `"stolen:dartmouth-proposal"`、`"demo:perceptron-line"`）；任务单没标的写 `[]`

## 7. 交付格式（写完必须报告）


## 8. 科普写作新规（2026-11-07 起生效，Boss 定调）

定位是**带科普性质的图书馆，不是检索工具**：严谨为骨，讲解为肉，幽默只在页边。

### 8.1 讲解性文字（正文内）

- 每个关键机制/术语首次出现后，必须跟一句**大白话再讲一遍**（生活类比），再回到准确表述。格式样板：
  「反向传播，就是把『猜错多少』从输出层一路倒着分账回每一层——像餐厅结账后把 A 菜多收的钱退回给切菜工。」
- 每章至少 2 处；类比之后必须补一句准确描述兜底，不能只留比喻。
- 比喻只为理解服务，不承载唯一事实；数字仍以已核验来源为准。

### 8.2 页边注段（可选新增）

- 标题 `## 页边注`，放于「档案」段之后。
- 2–4 条，馆长口吻调侃：时代错位、KPI 式吐槽、AI 自嘲。
- **红线**：每条必须由本章正文内已核验的事实支撑；禁止引入新事实、新数字、新人物；不调侃真实人物的苦难与过错。
- 样板：「提案原话说一个夏天就让机器学会使用语言、形成抽象与自我改进——七十年前的 KPI，至今没关单。」

### 8.3 字数口径不变

页边注计入正文汉字；全部章节仍 1500–2500。
