# 机忆书库 · 演示视频脚本与答辩提纲

> 用途：比赛提交的视频分镜 / 现场 3–5 分钟讲稿。视频以馆内「馆长导览自动版」为主线，8 站约 2 分 50 秒，后期配旁白与字幕即可。

## 一、视频信息

- 片长：3 分钟（导览 2'50" + 片头片尾 10"）
- 画幅：1920×1080，浏览器全屏，隐藏鼠标
- 录音：女声/男声均可，语速约 240 字/分钟
- 音乐：低音量环境铺底，无强节奏；不要盖过旁白
- 录制方式：本机 `http://127.0.0.1:3300/`，以访客身份入馆 → 点「导览」→ 录屏；片尾补 2 个特写镜头

## 三、必须补拍的 4 个特写（各 5–8 秒，后期插入）

1. **书轨发车**：点「书轨」，等 5 列车跑完一圈；字幕「5 条主线 · 55 站 · 31 条换乘」。
2. **阅读三栏**：开任意一章，展示左检索、右页边注、文末「下一章 / 本书目录 / 换乘章节」。
3. **残页**：打开 b1-c3，纸片掉落 → 捡起 → 残缺内容与馆员旁白；字幕「12 张残页，散在章节与展厅地板」。
4. **可玩演示**：打开 b6-c4 扩散演示，拖动步数；字幕「6 个可玩演示：图灵、中文屋、注意力、规则、扩散、缩放」。

## 四、现场答辩（3–5 分钟）

### 1. 一句话定位
「这不是一个 AI 百科，而是一座可以走进去的 AI 档案馆：用空间、线路与残缺页，把 90 年的技术史组织成可探索的路径。」

### 2. 讲稿骨架（约 4 分钟）

- **问题（30 秒）**：AI 史内容很多，但网页大多是「时间轴 + 卡片 + 外链」。评委记不住第 37 条，也不知道两条线索之间的关系。
- **做法（90 秒）**：把知识拆成三种空间关系——
  - 楼层 = 知识分级（公开 / 内部 / 机密 / 绝密）；
  - 书轨 = 主题线路（符号、神经、生成、行动、产业），带换乘；
  - 星图 = 书与书的引用/争论关系。
  再叠一层「不完整性」：残页、失窃页、躁动书页、历史分岔，让历史显得像档案而不是教科书。
- **实现（60 秒）**：原生前端 + three.js/Rapier；Fastify + node:sqlite；内容是 384 个 Markdown 文件，`npm run verify` 逐章校验字数、来源、双向关系；`npm run test:e2e` 88 项覆盖入馆、取书、检索、电梯、书轨、星图、异常馆藏与移动端。
- **收尾（30 秒）**：所有「假如」都明确标注为推测；所有史实章末给来源。我们想让读者带走的是一个可继续追问的问题，而不是一句结论。

### 3. 评委可能追问

| 问题 | 回答要点 |
| --- | --- |
| 和普通知识网站的区别？ | 空间即信息架构：楼层、线路、星图三种导航互为补充；内容不挂外链，每章 2000+ 字并给来源。 |
| 内容准确性怎么保证？ | 每章强制 3 条以上已核验来源；`verify` 卡字数、来源、关系；推测段落单独标注。 |
| 性能与低配设备？ | 2D 页面暂停 3D 渲染；低配自动降 DPR、关阴影、减粒子；手机默认进书架视图，3D 提供虚拟摇杆。 |
| 为什么做残页/失窃页？ | 档案天然不完整。让「缺失」成为玩法，读者才会注意史料是怎么丢的、谁在改写。 |
| 技术难点？ | 书轨的共享坐标系与防重叠布局；3D 与 2D 楼层状态同步；Rapier 碰撞下的后排可达；软件渲染环境的 E2E 稳定性。 |
| 后续计划？ | 前沿书架与 arXiv 定时入库、更多可玩演示、正式证书与备份监控。 |
