## 一句话

Google 扫描数百万本书只给检索摘要、复制 11,500 行 Java API 声明代码，分别在 2015 年第二巡回法院和 2021 年最高法院被判合理使用（不算侵权）；两案都没直说「拿版权作品训练模型算不算」，却把「转化性使用」「不替代原市场」两把尺子递给了后来的 AI 诉讼。

## 时间·人物·机构

2015 年 10 月 16 日，美国第二巡回上诉法院对 Authors Guild v. Google 作出判决（案号 13-4829）：Google 通过图书馆项目与 Google Books 复制了数千万本书，允许全文检索并显示片段；法院认定这种复制具有高度转化性，片段展示有限，不构成对原作品市场的显著替代，商业动机不足以否定合理使用；向图书馆提供数字副本也不侵权。

2014 年 6 月 10 日，同一法院在 Authors Guild v. HathiTrust（案号 12-4547）中认定，建立全文检索数据库、为残障读者提供可访问格式属于合理使用。2021 年 4 月 5 日，美国最高法院在 Google LLC v. Oracle America（案号 18-956）中以 6 比 2 判定 Google 复制 Java SE 的 API 声明代码属于合理使用；法院假定这些代码可受版权保护，重点谈四要素。Breyer 大法官撰写多数意见，Thomas 大法官异议，Alito 加入；Barrett 未参与。

## 为什么是这个时候

三个背景。第一，数字化把「复制」变成默认动作：扫描、索引、缓存、训练，每一步都在内存或磁盘里留下副本；如果每一次复制都要单独授权，搜索、无障碍访问、机器学习都寸步难行。第二，合理使用是开放式标准，不是清单：它要求看使用目的、作品性质、使用比例、市场影响，正好适合处理新技术。第三，AI 训练在 2016 年后从「小模型」变成「吃海量文本」，产业需要一个能解释「为什么可以先复制再学习」的先例；Google Books 与 API 案虽然不是为了训练，却提供了最接近的语言。

但「接近」不等于「适用」。Google Books 的转化是「让用户检索」，API 的转化是「让程序员在新平台调用」，两者都没有把作品变成模型参数。训练是另一种转化：它不展示原作，却可能让模型生成替代品。这个差别，是后来所有 AI 版权诉讼的战场。

大白话：这就像法院批准你把整座图书馆扫描成索引，不等于批准你把每本书读进脑子里再写一本相似的小说。准确地说，合理使用要逐案看目的与市场影响，先例只提供框架，不提供一刀切的许可。

## 怎么工作

先看四要素怎么落地。第一，目的与性质：Google Books 的检索被认定为转化性，因为它提供了「关于书的信息」，而不是「书本身」；API 案里，Google 复制声明代码是为了让程序员把已有技能带到新平台，也被认定为转化性。第二，作品性质：已出版的作品受保护，但法院更看重使用方式；API 案里，声明代码被视为与接口、想法绑在一起，创造性较弱。第三，使用比例：Google 复制了整本书，但只展示片段；Oracle 案复制了 11,500 行，占整个 API 2.86 万行中的 0.4%，法院认为这是「为转化目的所必需」的小部分。第四，市场影响：Google Books 的片段不替代买书；Android 不是 Java SE 的市场替代品，还让 Java 的接口进入新市场。

再看「转化性」的双刃。它让被告赢，也让原告学会怎么告：如果使用只是「复制 + 原样输出」，转化性就弱；如果输出替代了原作的许可市场，第四要素就重。AI 训练正好落在中间：训练过程不公开原作，但生成物可能与原作竞争。法院后来要问的，不是「训练有没有复制」，而是「训练的目的与生成物的市场效果」。

大白话：合理使用像做菜——你可以买一本菜谱，照着做出一桌新菜；但你不能把菜谱复印一遍，原封不动卖给别人。准确地说，转化的程度与市场替代的程度，是同一枚硬币的两面。

大白话：HathiTrust 的全文检索像给图书馆装了一台「只告诉你哪本书里有这个词」的检索机——它不把书给你，只给位置。准确地说，法院保护的是检索与无障碍访问这类不替代原作的用途。

## 它改变了什么

第一，它给大规模数字化留了空间。Google Books 之后，图书馆、档案馆、学术机构敢于做全文索引与无障碍访问，只要不提供替代原作的阅读体验。第二，它给软件接口定了调：复制 API 的声明代码，如果是为了兼容与迁移，可能被认定为合理使用；这直接影响后来的平台兼容与开源实践。第三，它给 AI 产业提供了论证模板：训练是「转化性」的，因为模型不存储原作、不向用户展示原作；但模板不是判决，原告可以攻击「生成物替代市场」这一环。第四，它让「市场影响」成为核心战场：不是看复制了多少，而是看复制后的产品是否抢了原作的生意。

数字上，Google Books 涉及「数千万本书」，Oracle 案涉及 11,500 行、0.4%、2.86 万行——这些数字后来被双方在 AI 诉讼里反复引用，用来证明「量小」或「量太大」。

## 今天的地位

三个判决都还是有效先例，没有被推翻。Google Books 与 HathiTrust 仍是图书馆数字化的安全边界；Oracle 案仍是 API 兼容性的重要参照，尽管它明确「不推翻此前的合理使用判例」。但它们在 AI 训练问题上的地位是「间接先例」：法院会引用它们的框架，不会直接套用结论。2021 年之后，生成式 AI 的诉讼把争点从「复制用于检索」推到「复制用于训练、生成物是否替代市场」，这三个判决成了双方共同的语法。

判断：作为「数字化合理使用」的基础，它们仍在用；作为「AI 训练是否合理使用」的答案，它们不够用，也从未自称够用。

## 争议与局限

第一，转化性标准太灵活。它可以让扫描整本书变成「转化」，也可以让一小段复制变成「侵权」，边界取决于法官怎么叙述目的。第二，市场影响难以量化。Google Books 的片段是否替代买书，API 是否替代 Java SE，都可以用经济学模型得出不同结论；AI 生成物是否替代原作，更难证明。第三，先例的事实基础不同。Google Books 的读者看到的是「片段」，AI 用户看到的是「完整生成物」；把前者类推到后者，等于把「不展示原作」当成「不替代原作」，这一步在逻辑上并不自动成立。第四，判决没有解决训练数据的授权市场：即使训练本身被认定合理使用，模型输出、风格模仿、数据库权利仍可能另案追究。

还有一条：合理使用是美国法概念。欧盟、英国、中国的规则不同，同样的训练行为在不同辖区可能得出不同结论；这让「先例」的跨国参考价值大打折扣。

## 关系

本章接在 b44-c3 之后：就业歧视问「谁被筛掉」，版权问「谁的作品被用来训练」。两者都涉及「大规模处理他人数据」，但前者看统计不利影响，后者看转化与市场替代。下一章会把版权与风险分级放进欧盟 AI 法案的框架；再往后，生成式 AI 的诉讼年直接检验本章留下的「转化性」模板。跨书看，b11-c6《版权》从技术侧讨论训练数据与模型输出，b11-c7《治理》则给出监管视角。三条线合起来，才能看清「合理使用」到底是护身符还是起跑线。
