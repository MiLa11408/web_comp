## 一句话

2023 年 10 月到 2024 年 4 月，三个基准把 Agent（智能体）从玩具房间赶进了真实世界：SWE-bench 让它在真实 GitHub 仓库里修缺陷，WebArena 让它在自建的完整网站里下单、发帖、改代码，OSWorld 让它在 Ubuntu、Windows、macOS 桌面上真的点鼠标。它们的共同结论很扫兴：演示里的聪明，进了生产常常只剩零头。

## 时间·人物·机构

SWE-bench 由普林斯顿大学的 Carlos E. Jimenez、John Yang、Alexander Wettig、Shunyu Yao、Kexin Pei、Ofir Press、Karthik Narasimhan 完成，2023 年 10 月 10 日提交 arXiv，2024 年进入 ICLR。它从 12 个常用 Python 仓库里收集 2,294 个真实 GitHub issue 及其对应修复补丁。

WebArena 由卡内基梅隆大学的 Shuyan Zhou、Frank F. Xu、Graham Neubig 等完成，2023 年 7 月 25 日提交。团队自建了四类完整网站：电商、社交论坛、协作软件开发、内容管理，并配上地图、用户手册等外部知识源。

OSWorld 由香港大学的 Tianbao Xie、Tao Yu 等联合多家机构完成，2024 年 4 月 11 日提交。它给出 369 个横跨真实网页与桌面应用的任务，支持 Ubuntu、Windows、macOS 三种系统，并公开环境、基线模型与评测脚本。

## 为什么是这个时候

到 2023 年，Agent 的「零件」已经齐了：ReAct 提供了「想一步、做一步」的循环，函数调用提供了机器可读的动作接口，多智能体框架提供了角色分工。可它们大多在 ALFWorld、WebShop 这类合成环境里考试：房间是简化的，网站是几十个商品搭出来的，任务短、状态干净、重开一把几乎零成本。

真实世界不配合。仓库有几千个文件，网页有登录和弹窗，桌面应用只有像素没有 API。恰好三件事在 2023 年成熟：公开的 GitHub issue 与测试用例，等于免费的「题目加标准答案」；容器与虚拟机快照，能把一台弄脏的机器几秒钟还原；大模型的长上下文与截图理解，勉强够读一段代码或认出一个按钮。于是评测单位从「一段文本」变成「一个可重置的环境」。

## 怎么工作

三个基准的骨架相同：给初始状态，让 Agent 操作，再用脚本检查世界变成了什么样。差别在「世界」是什么。

SWE-bench 的一道题是：仓库停在某个提交、附一段 issue 描述，模型要产出一个补丁。判卷不靠人读代码，而是把补丁打上去跑测试——原本失败的测试必须转绿，原本通过的测试不许转红。这意味着它同时考定位、跨文件修改和「别把别处弄坏」。论文报告，当时最强的闭源模型 Claude 2 只解决了 1.96% 的 issue；作者自己微调的 SWE-Llama 也只能处理最简单的一批。

打个比方，这不像考试里做一道函数题，更像把一辆开进修理厂的车交给你：先读故障单，再翻整车线路，最后必须让指定的灯灭掉、其他灯不许乱亮。准确地说，SWE-bench 用可执行的测试套件替代了文本匹配，把「代码说得对」改成「代码跑得过」。

WebArena 的一道题是：在自建电商里找一件满足三个条件的商品并下单，或在论坛里按规则回复某个帖子。四个网站都真的能点、能提交、能改状态；判分脚本检查订单、帖子、代码仓库的最终状态，而不是检查模型说了什么。论文里最好的 GPT-4 智能体端到端成功率 14.41%，人类是 78.24%。

OSWorld 更狠：369 个任务分布在真实应用里，比如在表格里改公式、把文件按类型归档、跨应用复制数据。每个任务都有初始状态配置和专门的执行检查脚本；Agent 只能看截图或辅助功能树，然后移动鼠标、敲键盘。人类能完成 72.36% 的任务，最好的模型只有 12.24%，论文把主要失败归给「界面定位」和「操作常识」。

打个比方，OSWorld 像把考生放进一间真办公室：桌上开着浏览器、表格和终端，题目是「把这份报表发出去」；监考不看你写得漂不漂亮，只看文件有没有到、格式对不对。准确地说，它用真实操作系统与真实应用做沙盒，以执行后的状态而不是对话内容判分。

## 它改变了什么

第一，它换了评测的计量单位。以前的基准是一个数据集，现在的基准是一套环境加一套验证器：环境怎么重置、观察给截图还是页面结构（DOM）、超时怎么算，都成了论文的一部分。第二，它把 Agent 工程的脏活摆上台面：上下文要装下整个仓库，观察要处理弹窗和加载，失败要能重试而不能把环境弄坏。第三，它给「演示 90 分」降了温：随身演示可以挑简单样本，公开基准不行；采购方开始要求可复现的运行记录，而不是一段剪辑视频。第四，它把人类水平重新变成参照系：14.41% 对 78.24%、12.24% 对 72.36%，差距让人一眼看出「能演示」和「能交付」不是一回事。第五，它催生了一类新基础设施：容器镜像、网站快照、测试编排、轨迹回放，评测本身成了一门工程。

## 今天的地位

判定是「基础仍在用，边界已被扩写」。三个项目都公开了代码、环境与评测脚本，原始论文的数字仍是 2023–2024 年的起点，后来的工作在这三个骨架上继续加题、加环境、加更细的失败分类。SWE-bench 成了代码 Agent 的公共试车场，WebArena 成了网页 Agent 的对照环境，OSWorld 成了桌面 Agent 的入门考。它们没有被取代，但也不再是唯一答案：真实生产里的权限、延迟、成本和长尾，仍然在基准之外。

## 争议与局限

第一是污染。题目来自公开 GitHub issue，训练语料也可能爬过同一批页面；模型可能记得补丁而不是学会修。WebArena 与 OSWorld 自建环境，污染轻一些，但会过拟合到特定网站布局和特定应用版本。第二是脆弱：自建网站会漂移，虚拟机镜像很大，检查脚本对时序和弹窗很敏感，同一个模型两次跑分可能不一样。第三是分布窄：12 个 Python 仓库不代表所有软件工程，英文网页任务不代表所有市场，桌面任务也偏消费级应用。第四是成本：一次评测要跑几十步、每一步都调用模型和工具，账单随步数线性上涨。第五是安全：一旦把真实权限交给 Agent，一次误删就是生产事故；「失败博物馆」里那类误删生产数据的桥段，在沙盒里是扣分，在机房里是停机。第六是二值判分：成功或失败掩盖了「差一步」和「差一百步」的区别。

## 关系

前置 b21-c7「多智能体」把单个循环复制成多个角色；本章则把循环放回真实环境，让角色们面对真实文件、真实网页和真实桌面。b21-c5 的 ReAct 提供了交错结构，b21-c6 的工具协议提供了动作接口，本章提供的是考场：没有它，前两章的进步只能靠演示证明。本章是 b21 的收尾，下一站交给 b22《开源大模型》——当 Agent 能改代码，权重和许可证就不再只是法律问题。

## 页边注

- 〔一句话〕演示里 90 分，进生产 30 分——丢掉的 60 分不是模型忘了，是环境开始收利息。
- 〔怎么工作〕SWE-bench 的判卷老师是测试：修好了灯亮，修坏了灯也亮——只不过亮的是红色。
- 〔争议与局限〕给 Agent 真实权限，像让实习生拿生产库钥匙：他可能真把活干完，也可能真把库删完。
