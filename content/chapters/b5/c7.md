## 一句话
2022 年 DeepMind 用同样算力、四倍数据训出 700 亿参数的 Chinchilla，打败 2800 亿的 Gopher，证明参数与训练量（token）该一起涨，行业从此从拼参数转向拼数据。

## 时间·人物·机构
2022 年 3 月 29 日，论文《Training Compute-Optimal Large Language Models》上线 arXiv。第一作者 Jordan Hoffmann，共同作者包括 Sebastian Borgeaud、Arthur Mensch、Elena Buchatskaya、Trevor Cai、Eliza Rutherford、Diego de las Casas、Lisa Anne Hendricks、Johannes Welbl、Aidan Clark、Tom Hennigan、Eric Noland、Katie Millican、George van den Driessche、Bogdan Damoc、Aurelia Guy、Simon Osindero、Karen Simonyan、Erich Elsen、Jack W. Rae、Oriol Vinyals、Laurent Sifre，全部隶属 DeepMind。

论文训练了 400 多个模型，参数从 7000 万到 160 亿以上，数据从 50 亿到 5000 亿 token。主角 Chinchilla 是 700 亿参数、1.4 万亿 token，算力与 Gopher（2800 亿参数、3000 亿 token）相同，约 5.76×10²³ FLOPs。结果是 MMLU 平均准确率 67.5%，比 Gopher 高 7 个百分点以上；在大量下游任务上同时超过 Gopher、GPT-3、Jurassic-1，以及参数量 5300 亿的 Megatron-Turing NLG。

## 为什么是这个时候
2020 年的缩放定律（b5-c6）给行业指了一条「堆参数」的路，GPT-3 1750 亿、Gopher 2800 亿、MT-NLG 5300 亿接连出现；但参数量越大，推理越贵。Chinchilla 论文指出，这些模型大多只训练约 3000 亿 token，而 Kaplan 的分配比例是在固定 token 数、固定学习率调度下拟合的——那会把「多训一会儿」的收益算低。

与此同时，DeepMind 手里有足够多的高质量数据和大规模实验平台，可以做一次真正的等算力对照：同样的钱，是买更大的模型，还是买更多的数据？答案是可以两者都买一点，但比例要改。

## 怎么工作
论文用了三种独立方法回答同一个问题。第一种：固定一组模型尺寸，让每个模型训练四种不同长度的学习率余弦周期，画出「损失—算力」的下包络，读出每个算力点最省的模型大小。第二种：固定算力，扫不同的参数与数据组合。第三种：直接拟合参数化损失 L(N,D)=E+A/N^α+B/D^β，再在 FLOPs≈6ND 的约束下求最优。

三种方法指向同一个结论：模型大小与训练 token 应大致同比增长——模型翻倍，token 也翻倍。换成比例，就是约 20 个 token 配 1 个参数；Chinchilla 的 1.4 万亿 token 除以 700 亿参数，正好是 20。

举个生活类比：固定一桌火锅的预算，肉（参数）和菜（token）要按比例一起加；只加肉不加水，锅会糊，只加水不加肉，汤会淡。准确地说，是在 FLOPs≈6ND 的约束下让损失对 N 与 D 的偏导相等，得到两者同步增长的最优点。

与 Kaplan 的差异可以写成一张对照：算力涨 10 倍时，Kaplan 建议模型涨 5.5 倍、token 只涨 1.8 倍；Chinchilla 认为两者各涨约 3.16 倍，也就是同比。差异的根源是实验设计：Kaplan 用固定学习率调度，余弦在 1300 亿 token 处衰减完毕，早期中间损失被当成最终损失，于是「小模型多训」显得不划算；Chinchilla 把调度长度与训练 token 数匹配，结论就翻了过来。论文也明确说，它同意 Kaplan 的一条判断：大模型不该训到最低损失，应显著早停。

验证方式很硬：不只看拟合曲线，还真训了一个按预测配置的模型。Chinchilla 用 Gopher 的算力预算，参数砍到四分之一、数据加到四倍，然后在大量下游任务上全面胜出。这不是「小模型运气好」，而是同一笔钱买到了更优的配置。附带好处是推理：70B 比 280B 小得多，微调与部署都更便宜。

## 它改变了什么
最直接的是把行业从「参数竞赛」推向「数据竞赛」。LLaMA 系列是清楚的后续：7B 到 65B 的模型在数万亿 token 上训练，LLaMA-13B 在多数基准上超过 175B 的 GPT-3，LLaMA-65B 与 Chinchilla-70B、PaLM-540B 竞争（LLaMA 论文摘要）。小模型只要吃够数据，就能逼近甚至超过大得多的模型，而部署成本低一个量级。

对开源社区，这条路线几乎是解放：单卡或小集群能跑 7B、13B，效果却不差；「能不能在本地跑」第一次和「效果好不好」放在同一张表上。对数据工程，重心从「买更多卡」转向「洗干净更多 token」——Chinchilla 论文自己就说，更大、更高质量的数据集是继续缩放的关键。

它还给「参数墙」换了一块牌子，叫「数据墙」：高质量 token 不是无限的，重复训练会递减；此后的竞争，一部分变成了数据来源与配比的竞争。

## 今天的地位
「计算最优」（compute-optimal）已经是预训练预算的通用语言：给定 FLOPs，先算最优参数量与 token 数，再决定集群开多久。Chinchilla 的 20:1 成了最常被引用的起点数字。它好用的地方正在于简单：一个比例就能把集群规模、训练时长与数据准备量串成一笔账。

但今天的实践常主动偏离 20:1。原因写在 Chinchilla 自己的结论里：它优化的是训练算力，推理成本只是「顺带降低」；如果一个模型要服务海量请求，把模型做小、把 token 加多，即使训练上「不最优」，总账也更便宜。LLaMA 让 7B 级模型也吃下万亿级 token，token 与参数之比远高于 20，就是这种思路的体现。

所以它的地位更像「重新校准了罗盘」，而不是「给出了永久航线」：方向（数据要和参数一起涨）被接受，具体比例仍随场景变。

## 争议与局限
20:1 不是自然常数。它来自特定架构、特定数据分布、特定优化设置下的拟合；换数据质量、换分词、换训练策略，最优点会移动。论文自己也把结论限定在「给定算力预算」的框架内。

它的目标函数只有预训练损失，不含下游任务、推理延迟、能耗与数据获取成本；「最优」是训练视角的最优，不是产品视角的最优。MMLU 67.5% 是一个基准上的数字，不能外推成「全面超过所有大模型」。

与 Kaplan 的冲突也提醒人们：缩放定律对实验协议极其敏感，同一个问题、两套拟合、两个答案，都能自洽地外推。后来者引用 20:1 时，往往省略了这些前提。

论文自己还留了一句伏笔：继续缩放的关键是更大、更高质量的数据集。当高质量 token 变得稀缺，20:1 所依赖的「数据管够」前提本身就会移动，配比也得重算。
